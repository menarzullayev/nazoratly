# nazoratly API (v1)

Holat: backend/API, MCP server, Telegram worker va Payme/Click callbacklari qurilgan va sinalgan (Python 3.13, FastAPI, psycopg3, PostgreSQL 16). To'liq endpoint ro'yxati: `clients/typescript/openapi.json` (kod bilan CI orqali sinxron saqlanadi) yoki ishga tushirilgan serverda `/docs`.

## Umumiy qoidalar
- **Identifikatorlar:** hamma resurs UUID bilan (ketma-ket raqamlar URL/javobda yo'q). Pul: `"500000.00"` ko'rinishidagi o'nlik satr, UZS, doim 2 xona.
- **Auth:** `POST /v1/auth/login` → `access_token` (JWT, 15 daqiqa) + `refresh_token` (opaque, 30 kun, har ishlatishda almashadi). Almashgan token qayta ko'rsatilsa butun sessiya bekor qilinadi (o'g'irlik belgisi). `Authorization: Bearer <access>`.
- **Bir nechta markaz:** foydalanuvchi bir nechta markazda a'zo bo'lishi mumkin; login `org_id` bilan yoki bitta markaz bo'lsa avtomatik; keyin `POST /v1/auth/switch`.
- **Rol har so'rovda bazadan tekshiriladi:** a'zolik to'xtatilsa yoki foydalanuvchi o'chirilsa, kirish darhol yopiladi (JWT muddatini kutmaydi).
- **Idempotency-Key** (ixtiyoriy, `POST` uchun, 8–255 belgi): bir xil kalit + bir xil tana → saqlangan javob (`Idempotent-Replayed: true`); boshqa tana → 422; hali bajarilayotgan → 409; xato (non-2xx) kalitni bo'shatadi. 24 soat saqlanadi, markaz+foydalanuvchi doirasida.
- **Sahifalash:** `limit` (1–200, standart 50) va `offset`; javob `{items, limit, offset, has_more}`.
- **Xato formati:** `{"error": {"code", "message", "details", "request_id"}}`. Kodlar: `validation_error` (422), `unauthorized` (401), `forbidden` (403), `not_found` (404), `conflict` (409), `unprocessable` (422, biznes qoidasi/FK/CHECK), `rate_limited` (429, `Retry-After`), `retry` (503, deadlock/serialization), `payload_too_large` (413), `internal_error` (500).
- **Kuzatuv:** har javobda `X-Request-ID` (kiruvchi qiymat qabul qilinadi); loglar JSON (structlog), parol/token redaksiya qilinadi; Sentry (`send_default_pii=false`) va OTLP trace faqat sozlanganda yoqiladi; `/health` (jonli), `/ready` (DB javob beradi).

## Rollar va ruxsatlar (`src/nazoratly/permissions.py`)
| Rol | Nima qila oladi |
|---|---|
| owner | hammasi (markaz profili, xodimlar, moliya, oylik tasdiqlash, agentlar, audit) |
| admin | owner'dan farqi: markaz profilini o'zgartirmaydi, owner/admin rolini bermaydi/o'zgartirmaydi |
| manager | o'quvchi/vasiy/rozilik, o'quv jarayoni, davomat, to'lovlarni yozish, hisobotlar, buxgalteriyani o'qish; xarajat, oylik, agent, audit yo'q |
| accountant | moliya (hisob, to'lov, xarajat), oylik tuzish/to'lash (tasdiqlash emas), hisobotlar, buxgalteriya (yozuv, ta'minotchi, ko'chirma; davrni yopmaydi); o'quvchi yozmaydi |
| teacher | faqat o'z guruhlari/darslari: ro'yxat ko'rish va davomat belgilash; o'quvchilarning umumiy ro'yxati yo'q |
| viewer | o'qish + agregat hisobotlar; qarzdorlar ro'yxati/to'lovlar yo'q |

Ikkinchi qatlam: Postgres RLS (`app.org_id`) — API xatosi bo'lsa ham boshqa markaz ma'lumoti ko'rinmaydi (testlarda tekshirilgan).

## Qo'shimcha servislar (bir xil image, alohida jarayon)
| Servis | Ishga tushirish | Vazifa |
|---|---|---|
| MCP server | `python -m nazoratly.mcp_server` (port 8001, `/mcp`, streamable HTTP, stateless) | Mijozning AI agenti uchun: `list_debtors`, `attendance_summary`, `revenue_report`, `list_reminder_targets` (read) va `draft_reminder` (draft). Har so'rovda `Authorization: Bearer nzt_...` (`agent_authenticate`), faqat `agent_v_*` view'lar, scope tekshiruvi, daqiqasiga cheklov, har chaqiruv (ok/denied/error) `agent_tool_calls` ga yoziladi. Hech narsa yubormaydi/to'lamaydi: draftni inson `/v1/agent-drafts/{id}/approve` bilan tasdiqlaydi. |
| Worker | `python -m nazoratly.worker` | Outbox'dan Telegram xabar yuboradi (`NAZORATLY_TELEGRAM_BOT_TOKEN`). DB'ga faqat `outbox_claim/complete` funksiyalari orqali (rol `nazoratly_worker`), `SKIP LOCKED` (bir nechta worker xavfsiz), yuborish paytida rozilik qayta tekshiriladi (bekor qilingan bo'lsa yuborilmaydi), qayta urinish backoff bilan (5 martagacha), 403/404 doimiy xato, bot tokeni hech qachon logga/DB'ga tushmaydi. **SMS: Eskiz.uz adapteri** (`NAZORATLY_ESKIZ_EMAIL/PASSWORD/FROM`; login → token keshlanadi, 401 da qayta login, 4xx doimiy xato, 5xx qayta urinish). Sozlanmasa SMS xabarlar aniq sabab bilan `failed` bo'ladi. |
| To'lov callbacklari | API ichida: `POST /pay/payme/{center_id}`, `POST /pay/click/{center_id}` | Payme Merchant API (JSON-RPC: Check/Create/Perform/Cancel/CheckTransaction, GetStatement; Basic auth; tiyin; holatlar 1/2/-1/-2; 12 soat timeout) va Click SHOP API (Prepare/Complete, MD5 imzo, xatolar 0..-9). To'lanadigan "hisob" = o'quvchi (`account.student` / `merchant_trans_id` = o'quvchi UUID). Bajarilgan tranzaksiya oddiy `payment` yaratadi va eng eski hisoblarga FIFO taqsimlanadi; Payme bekor qilish (qaytarish) to'lovni void qiladi va qarzni qayta ochadi. Markaz kalitlari `PUT /v1/payment-providers/{payme|click}` bilan (Fernet bilan shifrlanadi, `NAZORATLY_SECRETS_KEY`), `callback_url` javobda. |

## Muhim biznes qoidalari (kodda va testlarda)
- **Qarz hisoblanadi:** hisob − to'lov taqsimoti. To'lov `auto_allocate` bilan eng eski muddatli hisoblarga FIFO taqsimlanadi; ortig'i o'quvchi krediti (`credit`), keyin `/allocate-credit`.
- **Parallel xavfsizlik:** taqsimot to'lovni, so'ng hisoblarni (due_date, id) tartibida qulflaydi → parallel to'lovlar ketma-ketlashadi (8 parallel to'lov testi); qulf kutgandan keyin qoldiq yangi so'rovda o'qiladi (READ COMMITTED snapshot tuzog'i tuzatilgan). Guruh sig'imi ham qator qulfi bilan (6 parallel yozilishdan 1 tasi o'tadi).
- **Oylik hisob generatsiyasi:** har yozilish uchun oyiga 1 ta o'qish haqi (qayta ishga tushirsa ham takror yo'q); to'liq oy narxi, **proratsiya yo'q** (qaror kerak bo'lsa alohida); muzlatilgan yozilishlar hisoblanmaydi; chegirma foizi va individual narx hisobga olinadi.
- **Bekor qilish:** hisob/to'lov/xarajat o'chirilmaydi, `void` + sabab. To'lovni bekor qilish taqsimotni bo'shatadi; taqsimotli hisobni faqat `release_allocations=true` bilan.
- **Online to'lov:** `(method, external_ref)` bo'yicha idempotent — qayta kelgan Payme/Click so'rovi asl to'lovni qaytaradi (200), boshqa summa bilan 409.
- **Oylik:** yaratilgan qatorlar (`base`/`lesson`) qayta hisoblanadi, qo'lda qatorlar (bonus/jarima/tuzatish) saqlanadi; tasdiqlangach DB qatorlarni muzlatadi; tasdiqlash faqat owner/admin; bo'sh yoki manfiy yig'indi tasdiqlanmaydi.
- **Model B:** agent token `nzt_…` faqat SHA-256 sifatida saqlanadi; agent faqat `agent_v_*` view'larni o'qiydi va draft yaratadi; draftni inson tasdiqlaydi (`approve` → DB roziligi/vasiy bog'lanishini qayta tekshirib outbox'ga qo'yadi, rozilik bekor bo'lsa 422 va draft `pending` qoladi); 48 soatdan keyin draft `expired`.
- **Qabul hayot sikli (migratsiya 0011):** yozilish holati `trial` (ro'yxatda va davomatda bor, hisob yaratilmaydi, sig'imga kiradi). `GET/PATCH /v1/settings` (`trial_free_lessons` 1, `trial_free_days` 7); `POST /v1/groups/{id}/enrollments` `status: trial|active`; `GET /v1/trials/pending` (bepul dars YOKI kun chegarasi qaysi biri oldin tugasa, sabab bilan); `POST /v1/enrollments/{id}/accept {mode: full|prorated|free_until_next, accepted_on?}` birinchi oy hisobini yaratadi (proratsiya = guruhning shu oydagi darslaridan qolgani; dars bo'lmasa to'liq oyga qaytadi va `fallback_to_full: true`), `POST /v1/enrollments/{id}/drop`. Xatolar: `409 enrollment_not_trial`, `409 already_accepted`. `/charges/generate` sinovni va qabul oyini (va undan oldingi oylarni) hisoblamaydi.
- **Lead voronka:** `lead-sources`, `leads` (+`interactions`, keyingi aloqa sanasi), `POST /v1/leads/{id}/enroll-trial` (bitta tranzaksiyada o'quvchi + sinov yozilishi; takror chaqiruv birinchi natijani qaytaradi; bir xil telefon bo'lsa `409 duplicate_student`, `link_existing: true` bilan mavjud o'quvchi), `GET /v1/reports/funnel`. `enrolled` bosqichiga faqat konversiya olib boradi.
- **Umumiy "oltin" testlar:** qoidalar (`trial_status`, `first_month_charge`, `funnel_report`) Python (`backend/src/nazoratly/rules`) va TypeScript (`sheets/src/domain`) da ikki marta yozilgan; ikkalasi `tests/golden/*.json` dagi bir xil misollarni tekshiradi.
- **Sababli yo'qlik va qoplash (migratsiya 0012):** `settings`: `excused_mode` (`makeup` standart | `credit` | `none`), `makeup_expiry_days` (30), `makeup_lapses` (true). Davomatda `excused` belgilansa huquq yaratiladi (qayta saqlash takrorlamaydi; boshqa holatga o'tsa ochiq huquq bekor bo'ladi, qayta `excused` ochadi; sinov/muzlatilgan yozilish hech narsa olmaydi). `GET /v1/entitlements?status=&student_id=` (`effective_status` = `lapsed` muddatdan keyingi kuni), `POST /v1/entitlements/{id}/schedule` (qoplash darsi `lessons.kind='makeup'`; o'tgan sana 422, ochiq bo'lmasa `409 not_open`), `POST .../cancel`. Qoplash darsida `present/late` huquqni yopadi (`used`), `absent/excused` ochiq holatga qaytaradi; qoplash davomati faqat shu o'quvchini ko'rsatadi. `credit` rejimida kredit = oylik narx / oydagi darslar (yarim yuqoriga); `/charges/generate` ochiq kreditlarni eng eskisidan ayiradi (kredit to'liq ishlatiladi, ortig'i yo'qoladi; to'liq qoplansa 0 so'mlik hisob yoziladi: shuning uchun `charges.amount >= 0`). Oylik: qoplash darsi faqat kimdir kelgan bo'lsa hisoblanadi.
- **To'lov rejalari va PDF hujjatlar (migratsiya 0013):** `PUT /v1/charges/{id}/plan` (`{installments:[{amount,due_date}]}` yoki `{equal:{count,first_due}}`; 2..24 qism, yig'indi hisob summasiga teng, muddatlar o'sib boradi, aks holda `422` + `details.rule` = `count|non_positive|sum_mismatch|dates_not_increasing`; bekor qilingan hisob `409`), `GET`/`DELETE /v1/charges/{id}/plan`. Hisobning to'langan puli qismlarga eng eskisidan taqsimlanadi; qarz, muddati o'tgan summa (`overdue`, `overdue_amount`), `/students/{id}/balance`, `/reports/debtors`, `/reports/summary` va agent ko'rinishlari qism bo'yicha hisoblaydi (rejasiz hisoblar avvalgidek). Hisob muddati birinchi qismga o'rnatiladi (FIFO tartibi uchun); rejali hisobning summasi/muddatini `PATCH` qilish `409`, bekor qilish rejani olib tashlaydi. `GET /v1/reports/installments?days_ahead=&only_overdue=` ochiq qismlar. MCP: `list_debtors` da `overdue_total`, yangi `list_due_installments(days_ahead<=14)`.
- **Dars paketlari / abonement (migratsiya 0014):** guruh `billing_mode` (`monthly` standart | `package`) + `package_lessons` (1..200) va `package_price` (> 0) (`POST/PATCH /v1/groups`; oylik guruhda bu maydonlar bo'lmaydi, aks holda `422`; oylikka qaytarganda ular tozalanadi). `settings`: `package_expiry_days` (60, 1..730), `package_low_lessons` (2, 0..50). Paket = oddiy hisob (`kind='package'`) + `lesson_packages` qatori, shuning uchun to'lov/FIFO/kvitansiya/reja o'zgarmaydi: `POST /v1/packages {enrollment_id, purchased_on?, pay?:{amount,method,note?}}` (faqat faol yozilish va paket guruhi, aks holda `409`; `pay` bo'lsa to'lov shu paketga birinchi, qolgani FIFO). `GET /v1/packages?student_id=&group_id=&active=`, `POST /v1/packages/{id}/extend {expires_on}` (faqat keyingi sanaga, sotilgandan 730 kundan oshmasin; `422`). Paket beradigan darslar = `min(darslar, floor(to'langan * darslar / narx))` (qisman to'lov = proporsional). Davomat: `present`, `late`, `absent` bitta dars sarflaydi; `excused` faqat `excused_mode=none` bo'lsa; qoplash darsi, bekor qilingan dars, sinov, bekor qilingan sinov va qabul sanasidan oldingi darslar sarflamaydi. Paket guruhida `credit` rejimi pul krediti YARATMAYDI (dars sarflanmasligi o'zi kredit), `makeup` huquq yaratadi. Muddat: `purchased_on + package_expiry_days` (kun ham kiradi); muddatdan keyin ishlatilmagan darslar kuyadi (`burned`); qarz = paketsiz qatnashilgan darslar (manfiy dars), keyingi to'lov eskisini yopadi (muddati o'tmagan paketdan). `GET /v1/students/{id}/lesson-balance` (`available`, `burned`, `debt_lessons`, `balance_lessons`, `debt_amount` so'mda, `need` = `ok|low|exhausted|debt`, `next_expiry`), `GET /v1/reports/packages/payment-needed?need=` (eng yomoni birinchi, har qatorda eslatma MATNI TAKLIFI: hech narsa yuborilmaydi). Oylik hisob (`/charges/generate`) paket guruhlarini o'tkazib yuboradi (`skipped_package_groups`), sinovni qabul qilish paket guruhida hisob yaratmaydi, foizli oylik `package` hisobini `tuition` kabi sanaydi. MCP: `list_packages_needing_payment(limit)` (faqat AI roziligi bor o'quvchilar; agent matnni `draft_reminder` bilan loyihalaydi, inson tasdiqlaydi).
  Hujjatlar: `PATCH /v1/settings {requisites}` (markaz rekvizitlari), `POST /v1/documents/receipts {payment_id}` (to'lovga bitta kvitansiya, takror so'rov o'shani qaytaradi, bekor to'lov `409`), `POST /v1/documents/invoices {student_id, charge_id?}` (ochiq qarz qismlari; qarz yo'q `409 nothing_owed`), `GET /v1/documents`, `/documents/{id}`, `/documents/{id}/pdf`. Raqam `KV-yyyy-NNNNNN` / `TH-yyyy-NNNNNN` (markaz+tur+yil bo'yicha ketma-ket, teshiksiz). Hujjat chiqarilganda muzlaydi (snapshot+PDF o'zgarmaydi), fiskal da'vo yo'q (ichki hujjat). `POST /v1/documents/{id}/send {guardian_id}` = odam tasdig'i: vasiy o'quvchiga ulangan, Telegram chat va faol bildirishnoma roziligi bo'lsa outbox'ga navbat (rich xabar + PDF), aks holda `409`; takror chaqiruv ikkinchi xabar yaratmaydi. Worker avval `sendRichMessage` (400/404 da oddiy matn), so'ng `sendDocument`; PDF yuklash xatosida qayta urinish xabarni takrorlamaydi.

- **Boshqaruv paneli (5-bosqich, migratsiyasiz):** `GET /v1/dashboard?date_from=&date_to=&window_days=7&list_limit=200` (ruxsat `reports:read`: owner, admin, manager, accountant, viewer; o'qituvchi `403`). Standart davr: joriy oy boshidan bugungacha (sana markaz vaqt mintaqasida, `as_of`); `date_from`/`date_to` 0..1830 kun, aks holda `422`; `window_days` 1..60; `list_limit` 1..1000 (ro'yxatlar qisqartiriladi, sonlar to'liq). To'rt blok, bitta javobda: (1) `payments`: `paid`/`unpaid`/`overdue` va bosiladigan ro'yxatlar (`unpaid_students` summasi bo'yicha kamayish tartibida: `id`, `name`, `outstanding`, `overdue`, `package_debt_lessons`; `paid_students`). To'lamagan = ochiq qarz (qismlar bilan) YOKI paket guruhida manfiy dars; aholi = faol yoki muzlatilgan yozilishi bor o'quvchilar (sinov va ketganlar kirmaydi). (2) `movement`: `new`/`left` (+ ro'yxatlar), `trials_started`, `accepted`, `dropped`, `running`, `conversion` = qabul / (qabul + bekor), kutilayotgan sinovlar maxrajga kirmaydi. Yangi = birinchi haqiqiy qo'shilish (`accepted_on`, bo'lmasa `started_on`) davrda; ketgan = ochiq yozilishi yo'q va oxirgi tugash sanasi davrda; bekor qilingan sinov na yangi, na ketgan. (3) `finance`: oxirgi 6 oy (joriy oy bilan tugaydi): `income` (bekor qilinmagan to'lovlar), `operating` (bekor qilinmagan xarajatlar), `payroll` (tasdiqlangan/to'langan oylik; qoralama kirmaydi), `expenses = operating + payroll`, `net = income - expenses` (`/v1/reports/summary` bilan bir xil ta'rif) va jami. (4) `funnel` (`/v1/reports/funnel` bilan bir xil, shu davr) va `waiting`: `trials` (bepul dars yoki kun chegarasiga yetgan sinovlar, sabab bilan), `packages` (darsi bor, `window_days` ichida tugaydigan abonementlar), `rights` (`window_days` ichida kuyadigan ochiq qoplash huquqlari), `total`. Panel hech narsani qabul qilmaydi, sotmaydi, hisoblamaydi va yubormaydi. Hamma raqam `rules/dashboard.py` dan (oltin: `tests/golden/dashboard.json`, Sheets bilan bir xil).

- **Buxgalteriya (6-bosqich, migratsiya 0015):** `/v1/accounting/...`. Ruxsatlar: `accounting:read` (owner, admin, accountant, manager), `accounting:write` (owner, admin, accountant: qo'lda yozuv, hisoblar, ta'minotchi, ko'chirma), `accounting:close` (faqat owner, admin: davrni yopish); o'qituvchi va viewer `403`.
  - **Hisob rejasi:** `GET/POST /accounts`, `PATCH /accounts/{id}` (nom, faollik; kod va tur o'zgarmaydi; qoldig'i bor hisob faolsizlanmaydi). Birinchi chaqiruvda 15 hisobli shablon (1000 Kassa, 1010 Bank, 2000 Ta'minotchilarga qarz, 2100 Oylik qarzi, 3000 Kapital, 4000 O'quv to'lovlari, 4100, 5000-5090 xarajat turlari, 5100 O'qituvchilar oyligi) va ikkita pul hisobi yaratiladi; `GET/POST /cash-accounts`.
  - **Jurnal (o'zgarmas, hash zanjirli):** `GET /entries` (sana, hisob, manba filtri), `GET /entries/{id}`, `POST /entries` (qo'lda, muvozanatli, kelajak sanasiz; xato kodlari `details.errors`: `too_few_lines`, `bad_line`, `unknown_account`, `inactive_account`, `unbalanced`; yopilgan oy `409`), `POST /entries/{id}/reverse` (aniq teskari yozuv: har yozuv bir marta, teskari yozuv qayta bekor qilinmaydi; hujjatdan chiqqan yozuv hujjatni bekor qilish orqali tuzatiladi, `409`). Tahrirlash/o'chirish endpointi YO'Q; bazada UPDATE/DELETE/TRUNCATE hamma uchun rad etiladi, yozuv tranzaksiya oxirida muvozanatda bo'lishi shart, har qator oldingi qator hashiga bog'langan va hashni bazaning o'zi qayta hisoblab tekshiradi.
  - **Avtomatik yozuvlar (manba hujjat bilan bir tranzaksiyada):** to'lov (naqd: Dt 1000, boshqa usul: Dt 1010, Kt 4000; paket sotuvi va onlayn to'lov ham), to'lovni bekor qilish = qaytarish (teskari yozuv, bugungi sana), xarajat (`paid_from` cash|bank; Dt xarajat turi, Kt kassa/bank), oylik tasdiqlanganda (Dt 5100, Kt 2100) va to'langanda (Dt 2100, Kt 1000), ta'minotchi to'lovi. `POST /sync`: yozuvi yo'q hujjatlarni o'tkazadi, bekor qilinganlarni qaytaradi (idempotent; yopilgan oyga tushadiganlar `blocked`), `GET /pending` nima kutayotganini ko'rsatadi (0015 dan oldingi ma'lumot uchun).
  - **Hisobotlar:** `GET /ledger?account=&date_from=&date_to=` (qoldiq bilan hisob kartochkasi), `/reports/trial-balance`, `/reports/income-statement?date_from&date_to`, `/reports/balance-sheet?as_of` (joriy natija kapitalga qo'shiladi, `balanced` bayrog'i), `/reports/payables-aging`. Hisobot `rules/accounting.py` dan (oltin: `tests/golden/accounting.json`, Sheets bilan bir xil).
  - **Davr yopish:** `GET /periods`, `POST /periods/{yyyy-mm}/close` (faqat tugagan oy, kutayotgan hujjat yo'qligi va hash tekshiruvidan keyin; yopilgan oy qayta ochilmaydi, tuzatish keyingi ochiq oyda teskari yozuv bilan). `GET /verify`: zanjir va yopilgan davrlar (birinchi buzilgan qator `broken_seq`).
  - **Ta'minotchilar:** `/suppliers`, `POST /bills` (hisob xarajat yaratadi: Dt xarajat, Kt 2000; boshqaruv paneli ham sanaydi), `GET /bills?status=open|partial|overdue|paid|voided`, `POST /bills/{id}/payments` (qisman to'lov, qoldiqdan oshmaydi), `POST /bill-payments/{id}/void`, `POST /bills/{id}/void` (to'lovsiz hisob; xarajat ham bekor). Hisobning xarajati `/v1/expenses/{id}/void` bilan alohida bekor qilinmaydi (`409`).
  - **Ko'chirma bilan solishtirish:** `POST /statements` (pul hisobi, davr, boshlang'ich/oxirgi qoldiq), `POST /statements/{id}/lines` (kirim musbat, chiqim manfiy), `POST /auto-match {tolerance_days}`, `/lines/{id}/match {seq}` va `/unmatch`, `GET /statements/{id}` (`reconciliation`), `POST /finalize` (faqat qoldiqlar yig'indisi mos, hammasi moslangan va jurnal qoldig'i ko'chirma bilan teng bo'lsa; yopilgan ko'chirmani baza muzlatadi).

## Ma'lum cheklovlar
- Rate limit jarayon ichida (bir nusxa uchun aniq); ko'p nusxada har biri o'z oynasini yuritadi — parol taxmini uchun DB'dagi login qulfi (markaziy) ishlaydi. Ko'p nusxa kerak bo'lsa Redis/proksi limiti qo'shiladi.
- Access token (15 daqiqa) parol o'zgargandan keyin muddati tugaguncha amal qiladi; refresh tokenlar darhol bekor qilinadi. A'zolik/foydalanuvchi holati esa har so'rovda tekshiriladi.
- **Tashqi hisob/kirish kerak bo'lgani uchun haqiqiy provayderga qarshi sinalmagan:** Telegram (bot tokeni; sinov `httpx.MockTransport` bilan Bot API javoblarini taqlid qiladi), Payme/Click (merchant shartnomasi va kalitlar; sinov protokol hujjatidagi maydon/xato kodlariga qarab yozilgan o'z test mijozi bilan, Payme sandbox'ida ishga tushirilmagan). Ishga tushirishdan oldin provayderlarning test muhitida sinash shart.
- Eskiz adapteri Eskiz hujjatidagi endpointlarga qarab yozilgan (Postman kolleksiyasi), haqiqiy hisob bilan sinalmagan (hisob foyda boshlangach). Sheets edition `sheets/` papkada (Apps Script + Telegram); undan ko'chirish: `python -m nazoratly.tools.sheets_import` (sheets/README.md).
- Click qaytarish: `POST /v1/online-transactions/{id}/reverse` Click merchant API `payment/reversal` ni chaqiradi (`Auth: merchant_user_id:sha1(ts+secret):ts`; `merchant_user_id` provayder sozlamasida), Click rad etsa hech narsa o'zgarmaydi, qabul qilsa to'lov void bo'ladi. Click qoidalari: faqat joriy hisobot oyidagi kartali to'lov. Sinov Click javobini taqlid qiladi (`MockTransport`).
- Payme fiskalizatsiya (`SetFiscalData` / `detail`) amalga oshirilmagan: IKPU/package_code kerak, ular har markazning mahsulot kodlariga bog'liq va Payme bilan kelishiladi (spetsifikatsiyada ixtiyoriy).
- Kirishda markaz tanlash/QR/Telegram login yo'q; ota-ona portali yo'q (faqat xodimlar).
- Yuk (load) testi o'tkazilmagan; faqat mantiqiy va parallel (8 to'lov, 6 yozilish) testlar.
- Hisobotlarda `CURRENT_DATE` server vaqt zonasi bo'yicha (tushum hisoboti markaz vaqt zonasida).
