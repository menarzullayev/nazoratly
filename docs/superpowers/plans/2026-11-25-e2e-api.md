# E1: backend/API end-to-end journeys (plan)

Owner decision: a full automated E2E suite must exist before pilot customers. E1 owns `backend/tests/e2e/` only (E2 sheets, E3 web, D1 demo own the rest). Rules: `2026-11-24-overnight-program.md` sections 2 and 4.

## What "E2E" means here
Existing tests are per-feature (one rule, one endpoint family). `tests/e2e/` adds **multi-step business journeys through the real HTTP API on the real Postgres 16 harness** (no mocks of the database; Telegram and the AI worker are fake transports), plus **attack matrices** (cross-tenant RLS, role/permission) and **cross-cutting invariants** (Model B, outbox replay, money). A journey asserts the state after every business step and an invariant at the end (journal balances, FIFO, no negative surprises). Shared builders are imported from `tests.helpers` and the existing test modules; nothing is duplicated.

Rules for the suite: dates only via `tests.helpers.org_today()`; no sleeps; no real network; no test depends on another's data (each journey uses fresh `make_tenant`); deterministic. CI cost target: the whole `tests/e2e/` dir under ~3 minutes on the shared session-scoped Postgres.

## Files (one per journey group)
| File | Journey |
|---|---|
| `test_j01_admission_money.py` | lead -> trial -> accept -> enroll -> attendance -> charges with discounts -> partial payment -> refund -> cash close -> period close -> accounting reports (trial balance, income statement, balance sheet, verify chain) |
| `test_j02_schedule.py` | schedule with room/teacher conflicts, substitute, lesson move (notice draft needs approval), payroll effect, cancel |
| `test_j03_growth.py` | referral + promo credit applied to the next charge, source ROI, lead reminders send nothing |
| `test_j04_results.py` | marks, exam, progress report PDF (draft -> approve -> send), certificate + public verify |
| `test_j05_ai.py` | AI reports with fake transport: anonymized prompt (codes not names), names switch, rule-based fallback, daily limit, nothing sent |
| `test_j06_branches.py` | two branches: data + permission separation, student transfer, per-branch and total reports, cash close per branch |
| `test_j07_guardian.py` | guardian linking by all four methods; every guardian action waits for approval; no push on decision |
| `test_j08_teacher.py` | teacher invitation -> accept -> own groups only -> attendance -> unmarked-lesson reminders -> guardian message limits + log |
| `test_x01_tenant_isolation.py` | cross-tenant read/write/id-guessing attacks over every list/detail endpoint family; raw-SQL RLS under the app role |
| `test_x02_permission_matrix.py` | role x endpoint matrix (owner/admin/manager/accountant/teacher/viewer) |
| `test_x03_model_b.py` | nothing outbound without approval, asserted on the fake Telegram transport across all producers |
| `test_x04_outbox_idempotency.py` | outbox claim/complete replay, worker double-run, Idempotency-Key replay on money endpoints |
| `test_x05_money_invariants.py` | journal always balances, FIFO allocation, no negative balances, void/refund restore, concurrent payments |

## Bugs
Real product bugs found by journeys are fixed in separate commits (`fix(...)`), each with a regression test inside the journey that found it, and listed in the PR/report.

## Local checks (all must pass before push)
`cd backend && uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest`.
Delivery: PR, wait for all 7 CI checks, rebase on latest `origin/main`, re-run, squash-merge own PR.
