# Plan: G5 AI assistant (session S5, slug `ai`, migrations 0040-0044)

Scope source: `docs/superpowers/specs/2026-11-24-product-expansion-2-design.md` section 4 G5 and the overnight program.
Everything here is a suggestion or a draft. Nothing is sent to a guardian, student or lead by this code (Model B).

## 1. Items (all delivered, none deferred)

| # | Item | API product | Sheets edition |
|---|---|---|---|
| 1 | Weekly owner summary | rule numbers + AI text (fallback: rule text) | rule-based report, same formulas |
| 2 | Debt follow-up advice (who first, tone, draft text) | rules order/tone/draft + AI advice and drafts | rule-based list, same formulas and draft texts |
| 3 | Churn-risk list (attendance drop, debt, no answer after trial) | rule score + AI advice | rule-based list, same formulas |

Extra per-center switches (privacy): `ai_enabled` (default true) and `ai_daily_limit` (default 20 AI reports a day).

## 2. Shared rules (golden tested in both products): `tests/golden/insights.json`

Pure functions in `backend/src/nazoratly/rules/insights.py` and `sheets/src/domain/insights.ts`. Whole so'm, integers.

* `debt_followup(students, today)`: for students with outstanding > 0. `age_days` = days since the oldest overdue due date
  (0 when nothing is overdue). `tone`: no overdue amount -> `reminder`; age <= 7 `soft`; <= 30 `firm`; else `final`.
  `score = min(60, 2 * age_days) + min(40, outstanding div 100000)`. Order: score desc, id. Draft text per tone in Uzbek Latin
  (`debt_message`); no late penalty, no threats.
* `churn_risk(students)`: attendance points = min(40, previous% - recent%) when both windows have >= 2 marked lessons and the
  rate fell; debt points = min(30, overdue age days); trial points = 10 + min(20, 5 * days over the trial limit) for an
  undecided trial. `score = min(100, sum)`; level `high` >= 60, `medium` >= 30, else `low` (low is not listed). Reasons:
  `attendance_drop` (points >= 10), `debt` (age > 0), `trial_no_answer`. Order: score desc, id.
* `weekly_summary(facts)`: income and previous week, change %, expenses, net, new/left students, unpaid count and total,
  overdue count, attendance % for the week and the previous week, high/medium risk counts, and the report lines.
* Percentages use integer half-up arithmetic so both languages agree exactly.

## 3. Backend design

* Migrations (up + down, `db/tests/test_schema.sql`):
  * `0040_ai_settings`: `org_settings.ai_enabled`, `ai_sees_names`, `ai_daily_limit`.
  * `0041_ai_reports`: `ai_reports` (kind, period_end, source `ai|rules`, model, fallback_reason, content, data jsonb, created_by),
    RLS, grants, audit trigger, immutable rows (a report is a record of what was suggested).
* `ai_transport.py`: `AiTransport` protocol, `HostWorkerTransport` (HTTP + bearer token to the host worker), `AiUnavailable`.
* `ai_privacy.py`: `Pseudonymizer` (names -> `S001`, restored only for known tokens, unknown tokens left as is).
* `ai_reports.py`: facts loaders (RLS connection), prompt builders, orchestration with fallback, persistence.
* `ai_host_worker.py`: stdlib HTTP server for the host; builds the lean `claude -p` command (`--tools ""`, no MCP, no slash
  commands, no session persistence, no setting sources), runs it with a timeout, one request at a time, bearer token.
  The claude command prefix is configurable (`NAZORATLY_AI_CLAUDE_CMD`, e.g. the `pro` launcher). Never started by tests or CI.
* `routers/ai.py`: `POST /v1/ai/reports`, `GET /v1/ai/reports`, `GET /v1/ai/reports/{id}`; settings through `/v1/settings`.
  Permission `reports:read`. A transport is taken from `app.state.ai_transport` (tests inject a fake).
* Config: `ai_worker_url`, `ai_worker_token`, `ai_model` (default `haiku`), `ai_timeout_s`. docker-compose passes the variables
  (empty = AI not configured = rule-based reports). The container never holds `claude` credentials.

## 4. Sheets design

* `sheets/src/domain/insights.ts` mirrors the rules; `sheets/src/gas/insights.ts` builds three report sheets
  ("Hisobot: haftalik xulosa", "Hisobot: qarz bo'yicha maslahat", "Hisobot: ketish xavfi"; no "AI" in the name: there is none) from existing sheets. Menu "Hisobotlar (qoidalar bo'yicha)".
* No new OAuth scope: only the spreadsheet scope is used. The reports say honestly that they are rule-based.

## 5. Tests (test-first)

* Golden: Python and TypeScript read the same `insights.json`.
* Backend: negative tests for each switch (disabled, limit reached, transport error, bad output, injected tokens), privacy test
  (no real name, phone or id in the prompt when anonymized; names present only when the center allows), permission and RLS tests,
  facts loading from real data through the HTTP API, host worker command and handler with a fake runner, HTTP transport with
  `httpx.MockTransport`. No real `claude -p` anywhere.
* Sheets: harness tests for the three reports; schema/ALL_TABLES unchanged (reports are generated sheets, not data tables).

setting `NAZORATLY_AI_WORKER_URL/TOKEN` in `.env`; `clasp push` and trying the new Sheets menu.
