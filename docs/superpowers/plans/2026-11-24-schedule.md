# Plan: G2 schedule and rooms (session S2, slug `schedule`, migrations 0025-0029)

Scope (design section 4, G2), all of it, both products:

1. Calendar view (week/day) of all groups for owner and teacher.
2. Rooms with capacity; warn when a group's capacity does not fit the room; room/time and teacher/time conflict checks on save.
3. Substitute teacher per lesson; payroll goes to the substitute.
4. Lesson move/cancel; guardians' notification DRAFT is prepared, a person approves; payroll effect computed.

## Shared rules (golden: `tests/golden/schedule.json`, Python `rules/schedule.py`, TS `domain/schedule.ts`)

| Rule | Meaning |
|---|---|
| `overlaps` | two same-day intervals overlap when `a.start < b.end and b.start < a.end` (touching ends do not) |
| `find_conflicts` | a candidate lesson against existing ones on the same date: room clash, teacher clash (effective teacher); cancelled lessons never clash; the candidate itself is ignored by id |
| `capacity_check` | `ok` / `group_capacity_over_room` (group capacity > room capacity) / `enrolled_over_room` (no group capacity, enrolled > room capacity); unknown capacity = ok |
| `effective_teacher` | substitute, else the lesson's teacher, else the group's teacher |
| `payroll_effect` | per-lesson teachers only: cancel = effective teacher loses the rate; substitute = old effective teacher -rate, substitute +rate; move across a month = -rate in the old month, +rate in the new month; fixed/percent teachers are unaffected (their pay does not depend on one lesson) |
| `change_message` | Uzbek guardian text for cancel / move (substitute is not messaged) |
| `parse_schedule` (Sheets text -> slots) | `Du-Chor-Ju 18:00-19:30`; a missing end time means 90 minutes |
| `week_range` | Monday..Sunday around a date |

## Postgres / FastAPI (migrations 0025-0026)

- 0025: `lessons.substitute_teacher_id`, `cancel_reason`, `original_date`, `original_start_time`; table `lesson_changes` (kind move/cancel/substitute, old/new values, reason, actor); table `schedule_notices` (guardian message drafts per change: pending/approved/rejected/sent, outbox link). RLS, audit, grants, down migration, `test_schema.sql`.
- Endpoints (all `/v1`): `GET /calendar` (week/day, owner/admin/manager all, teacher own incl. substitute; entries carry conflict and capacity flags), `GET /schedule/checks` (conflicts + capacity warnings for a date range), `POST /lessons/{id}/move|cancel|substitute`, `GET /lessons/{id}/changes`, `GET /schedule-notices`, `POST /schedule-notices/{id}/approve|reject` (approval queues the outbox message through the existing DB compliance trigger), `/ui/calendar` page.
- Save-time checks: lesson create/patch/move, weekly schedule put, substitute set -> 409 `schedule_conflict` with details unless `allow_conflict=true`; schedule put returns capacity warnings.
- Payroll: per-lesson lines use `COALESCE(substitute, lesson teacher, group teacher)`. A lesson already in an approved/paid payroll cannot be cancelled/moved across months/substituted (409).
- Model B: notices are only drafts; nothing is queued until a person approves.
