# E3: browser end-to-end tests for the web surfaces

Scope (owner decision: a full automated E2E suite before pilot customers). This session owns `web/e2e/**`, a test-stack harness
and front-end fixes in `web/` and in the API-served pages `backend/src/nazoratly/ui/`. It does not touch `sheets/` or backend
business logic.

## Part A. Landing (static export, `web/`, Playwright against `out/`)

New spec `web/e2e/landing-full.spec.ts`, run for all five routes (`/`, `/uz-cyrl/`, `/uz-new/`, `/ru/`, `/en/`):

1. Content: h1, every section, 10 + 8 capability cards, 10 FAQ items, pricing, contacts present.
2. No untranslated keys: no `{{`, `undefined`, `[object`, `NaN`, no dictionary key shaped text (`features.more.0`) in visible text.
3. Script check: Cyrillic route has Cyrillic letters in headings and no Latin-only copy outside brand terms; new-Latin route uses the 2026 letters (`ö`, `ğ`, `ş`, `ç`, `ñ`...) and contains no Cyrillic; old Latin has no Cyrillic.
4. Language switch: from every locale, click each language link and land on the right path with the right `lang`.
5. Console clean: no `console.error`/`pageerror`, no failed requests (4xx/5xx) while loading and scrolling.
6. No broken links/images: every internal `href` returns 200 (anchors resolve to an id), every `<img>` has loaded (`naturalWidth > 0`).
7. Viewports: desktop 1280x800 and mobile 390x800 (no horizontal scroll, header usable).
8. Demo role buttons (owner/teacher/guardian) on all five routes; every expansion-2 card and FAQ item opens/reads.
9. Axe (WCAG A/AA) on all five routes x both viewports, 404 page, and the open-FAQ state.

Lighthouse: unchanged gate (`--min 95`, both presets). Run once locally with `--min 95`; mobile 100 is checked on the output.

## Part B. API-served pages (browser tests against a stack the test run starts itself)

Harness `backend/tests/e2e_stack.py` (python, run as `uv run python -m tests.e2e_stack`):
disposable Postgres 16 in Docker (tmpfs, random port, unique name, removed on exit), all migrations, the real FastAPI app on a
random free port via uvicorn in the same process, a fake Telegram transport (`httpx.MockTransport`, no network), a test bot token.
A second tiny "control" server on another random port exposes only to the test: seeded ids/credentials, `initData` signing
(HMAC with the test bot token only), the fake Telegram outbox (to read login codes), link-code issue.
Playwright `globalSetup` (`web/e2e-api/global-setup.ts`) starts it, waits for a `READY {json}` line, exports base URLs, and
`globalTeardown` stops it. Separate Playwright project `api-ui` (own config `playwright.api.config.ts`), `npm run e2e:api`.
Never uses 8010/8012 or the live compose project.

Flows:

- Guardian portal: phone -> code arrives in fake Telegram chat -> code verify -> cabinet; wrong code error; consent screen; tabs
  (attendance, balance, documents, schedule, results, requests); the four linking methods' UI parts: Mini App `initData` sign-in
  (valid, tampered, expired, not linked, several centers choose-list), portal phone-code (code from one-time link code / phone),
  QR card code and manual link are staff/bot side: the browser part is the cabinet that opens after each.
- Approval-required actions: absence reason, payment promise, make-up choice show "kutilmoqda" (pending approval), can be
  withdrawn; nothing applied before approval.
- Teacher Mini App: sign-in by signed `initData` and by email/password, roll call (mark + save + counter), grade/note, week, pay,
  guardian message with daily limit, inbox; QR scan page with a fake camera (Chromium `--use-fake-device-for-media-stream`
  with a generated QR y4m/mjpeg) and the hardware-scanner/manual path.
- Calendar: week/day, prev/next, conflict/cancelled pills, schedule notices approve/reject.
- Import wizard: paste CSV with good, duplicate and bad rows -> mapping -> error rows -> commit (skip/abort).
- Documents: receipt/invoice PDF, monthly progress report PDF, certificate PDF download (valid `%PDF` bytes) and open.
- Axe on every API-served page (login state and logged-in state) and console-error check.

## Part C. Delivery

Local: `npm run lint && npm run typecheck && npm test && npm run build && npm run e2e && npm run e2e:api`, Lighthouse once with
`--min 95`; backend `ruff`/`mypy` for the harness. CI: the existing `web` job keeps landing e2e; a new parallel job `web-ui`
runs the API-served browser tests (docker + uv). Bugs found: separate commits with a regression test each. Rebase on
`origin/main`, wait for all checks green, squash-merge.
