# D1: demo materials (2026-11-25)

Scope (owner decision): sell through 30-day free pilots; the demo is shown four ways (Sheet copy link, interactive site demo, video, live call). This session owns only demo data, `sheets/src/gas/demo.ts`/`setup.ts` sample loader and their tests, `docs/DEMO.md`, plus one small landing check. No `web/` test files of E3, no `sheets/test/e2e/` of E2, no live steps.

## Design

1. **Sheets sample data covers every new capability.** `loadSampleData` additionally writes (all flagged `demo`, dates relative to today, only when the target sheet exists so older workbooks keep working):
   - money: two discounts (scholarship 20%, individual amount) with discount lines, a refund (`to_credit` + a cash `leaving`), a cash close with a difference and its note (not posted to the journal: demo money never enters the books);
   - schedule: rooms, group schedules, two groups in the same room at overlapping times (conflict warning), a substitute teacher on one lesson;
   - growth: referral (rewarded, credit entitlement), promo code and its use, source costs;
   - results: lesson marks + month marks, an exam with results, an approved monthly report, a certificate;
   - guardian: a pending link request (QR) and a payment-promise request awaiting approval;
   - teacher: a pending invitation (hash of a fixed, public demo code, never a real secret);
   - branches: a second branch "Chilonzor filiali" with the Matematika group (children follow the group);
   - AI rule-based report: no table, the weekly summary / debt tone / risk list are computed from this data; the test proves they are non-empty.
2. **Demo flag on the new tables.** `schema.ts` gets an optional `Demo` column on every table that the sample now writes (ROOMS, SCHEDULE_CHANGES, REFERRALS, PROMOS, PROMO_USES, ENTITLEMENTS, MARKS, EXAMS, EXAM_RESULTS, REPORTS, CERTIFICATES, CASH_CLOSES, GUARDIAN_REQUESTS, GUARDIAN_LINKS, TEACHER_INVITES, BRANCHES). `optional` so a workbook set up earlier still reads. These move from "real only" to flagged specs in `gas/demo.ts`: clearing removes only flagged rows and still refuses when a real row references a demo row (now also by branch).
3. **Website demo (`web/demo`)**: separate seed in TypeScript, not shared with `sheets/src/domain`. Only touched if a small additive change fits E3's tests; otherwise reported as not done with the reason.
4. **Copy link**: `docs/DEMO.md` documents publishing (`.../copy`), `NEXT_PUBLIC_DEMO_SHEET_COPY_URL` (build-time), and the empty-env behaviour. A test pins that the landing renders no dead link when the variable is empty.
5. **Video scripts and live run-sheet** (Uzbek Latin) in `docs/DEMO.md`: 90 s owner story, 60 s teacher+guardian Telegram story, 15 min live call, objections, what not to promise, owner-setup-dependent parts marked, pre-call checklist.

## Tests

- `sheets/test/demo.test.ts`: sample covers each capability (row counts per table), every row flagged, clear removes only flagged rows (and deletes second branch), clear refused for a real row pointing at a demo branch, refresh keeps Telegram links, no journal postings, weekly summary non-empty.
- Existing counts (3 groups, sheets list) updated.
- `npm test` + `npm run build` in `sheets/`; `web` checks if `web/` is touched.

## Delivery

PR, 7 CI checks green, rebase on latest `origin/main`, squash-merge. Owner by hand: publish the Sheet copy link, set the env var, orchestrator rebuilds the web container.
