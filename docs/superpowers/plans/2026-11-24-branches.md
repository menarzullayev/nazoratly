# G6 multi-branch (session S6, slug `branches`, migrations 0050-0059)

Decisions (owner, design section 4 G6): branches inside ONE center, one owner, one books; a branch mark on every row; students may move between branches; reports total and per branch. Separated by branch: cash and reports, staff permissions (admin/teacher see only their branch), prices and settings.

## 1. Model

- `branches` already exists (name, address, status). New: `is_default` (exactly one live default per center; every center gets one: backfill + trigger on new centers). `memberships.branch_id` already exists: NULL = center-wide staff (owner), set = restricted to that branch.
- **Branch mark** = `branch_id` (FK `(org_id, branch_id)`) on every business row. Marked tables are in three kinds:
  - *people/assets*: students, guardians, teachers, study_groups, rooms, leads (+ expenses, which already had it);
  - *derived from a parent* by trigger: group_schedules, enrollments, lessons, attendance, charges (enrollment, else student), charge_installments, discount_lines, student_discounts, lesson_packages, absence_entitlements, payroll (teacher), exams/results, learning_marks, progress_reports, certificates, waitlist, lesson_changes, schedule_notices, refunds, referrals, promo_redemptions, documents, outbox, data_consents, student_guardians, online_transactions, supplier bills/payments, lead_interactions;
  - *money/context*: payments (+ allocations), cash_closes, journal_entries/lines, lead_source_costs, ai_reports, audit_log.
  - **Shared (not marked, NULL = every branch)**: courses, lead_sources, suppliers, chart of accounts, promo campaigns, referral programs, org_settings, accounting_periods (month close is center-wide), cash_accounts/bank_statements/statement_lines (nullable mark).
- One trigger function `stamp_branch()` fills the mark when the writer did not: explicit value > (context first for money rows) session scope `app.branch_id` > parent row > the center's default branch. So existing endpoints, import and demo seed keep working unchanged.
- **Separation = RLS.** `app_branch_id()` reads `app.branch_id`. Every marked table gets a RESTRICTIVE policy `branch_scope` (`app_branch_id() IS NULL OR branch_id = app_branch_id()`), on top of the tenant policy. Restricted staff (membership.branch_id set) always run with `app.branch_id` = their branch: every list, report, cash balance and ledger query is automatically per branch. Center-wide staff can narrow ("view as branch") with header `X-Branch` (public id of the branch); without it they see the total.
- Immutable rows: money rows cannot change branch (trigger). The journal stays immutable; the only allowed UPDATE is stamping a NULL branch once (backfill), the hash chain does not include the branch. Journal checking triggers become SECURITY DEFINER so the hash chain is verified on the whole ledger while a branch session writes.
- **Student move**: `POST /v1/students/{id}/transfer` (center-wide staff only): changes the student's branch and his guardian links, keeps history and money in the branch where it arose, writes `student_branch_moves`. Active enrollments in groups of the old branch must be ended (`end_enrollments=true`) or the move is refused (409). Invariant (DB trigger): an active/trial/frozen enrollment's student and group are in the same branch.
- **Prices**: `branch_course_prices(branch, course, monthly_fee)` = the default fee when a group of that branch is created without one; group fee stays authoritative for billing (charge generation is not touched). **Settings**: `branch_settings` (NULL column = inherit org value); `load_settings(conn, org_id, branch_id)` resolves the effective value, consumers pass the row's branch.
- **Cash**: the daily cash close is per branch (unique per branch/date/shift); the book balance is the cash accounts of the ledger filtered to the branch. Center-wide staff with several active branches must pick one (`X-Branch` or `branch_id` in the body), else 422.
- **Reports**: `GET /v1/branches/report?month=` returns one row per branch + a total row (students, groups, revenue, charges, expenses, debt, cash); the total equals the sum of the rows (golden invariant).
- Permissions: `branches:read`, `branches:manage` (center-wide owner/admin only). Restricted staff cannot create branches, move students between branches, close ledger periods or verify the whole chain.

## 2. Sheets (parity)

- Tabs `Filiallar` (branches) and `Xodimlar` (email, role, branch), `Filial narxlari`, `Filial sozlamalari`; optional column `Filial` on every business tab (missing column = default branch, so a not-yet-updated workbook keeps working).
- `repo.read/append` apply the scope (the RLS analogue): restricted staff (listed in `Xodimlar` with a branch) read and write only their branch; the owner can pick a view branch (stored per user); stamping uses the same rule as the server (golden). Honest limit: Google Sheets cannot hide cells from a user who opens the tab directly; the scope applies to the menus, reports and actions of the script.
- Menus: Filiallar (list/add/close), Filialga ko'chirish (student), Filial hisoboti (per branch + total), Filial tanlash.
- No new OAuth scope (`userinfo.email` is already declared; user properties need none).

## 3. Shared rules and golden tests (`tests/golden/branches.json`)

`stamp_branch` (precedence), `row_visible` (scope), `branch_totals` (per branch + total, sum invariant), `transfer_check` (refusals), `effective_value` (settings/prices inheritance), `cash_close_branch` (branch required or not).
