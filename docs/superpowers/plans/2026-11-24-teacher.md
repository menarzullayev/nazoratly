# G8 teacher app (session S8, slug `teacher`, migrations 0065-0069)

Scope (design section 4, G8), both products (Postgres/FastAPI and the Google Sheets edition), shared golden tests:

1. **Entry ways**: Telegram bot first, Telegram Mini App and plain API login too. The owner invites a teacher (one-time code); the teacher sees only his own groups.
2. **Teacher work**: marks attendance (also by QR scan), writes notes/grades, sees own hours and pay, groups and schedule.
3. **Reminders**: a lesson not marked X hours after it ended reminds the teacher; an end-of-day list of unmarked lessons goes to the owner. Internal (staff) only, never to guardians.
4. **Direct guardian messages** (a person's explicit action, Model B stays intact): own groups only, every message logged and not deletable by the teacher, daily limit, templates plus free text, the owner can switch the right off per teacher.

## Decisions taken here (all reversible, no owner input needed)

- A teacher account is a normal `users` row + `memberships(role='teacher')` + `teachers.user_id`. Invitation = `teacher_invitations` (code `T-XXXXXXXX`, only the SHA-256 is stored, 7 days, single use). Accepting it: in the bot (`/start T-XXXXXXXX`: the Telegram user becomes the account, `users.telegram_user_id`) or through the API (`POST /v1/auth/accept-teacher-invite` with email + password, then the normal login). One teacher profile = one account.
- Mini App login: `POST /v1/auth/telegram-miniapp {init_data}`: HMAC check with the bot token, `auth_date` at most 1 day old, the Telegram user must already be linked to a teacher (or other staff) account. Disabled (404) when `NAZORATLY_TELEGRAM_BOT_TOKEN` is not set. The page `/ui/teacher` reads `tgWebAppData` from the URL fragment (no third-party script, the CSP stays `script-src 'self'`).
- QR scan: the existing `POST /v1/attendance/scan` + `/ui/scan` camera page (teacher role may scan only own lessons). The Telegram bot cannot read a camera, so the bot offers marking by buttons and the Mini App links to the scanner.
- Hours and pay: hours = minutes of lessons `held` in the month (the teacher as `COALESCE(substitute, teacher, group teacher)`) / 60, one decimal. Pay estimate: `fixed` = rate, `per_lesson` = held lessons x rate, `percent` = collected tuition x rate / 100 (same as payroll generation); once a payroll row exists for the month its status and total are shown too. Whole so'm.
- "Unmarked lesson": status not `cancelled`, ended (date + end time in the center's time zone) at least X hours ago (center setting `reminder_after_hours`, default 2) and no attendance row at all (a `held` lesson without rows counts). Teacher reminder once per lesson (dedup key). Owner digest after `digest_after` (default 20:00 local), once per day, only when something is unmarked, lists lessons of that day.
- Guardian message limits: right on (per teacher, default on), student in one of the teacher's own groups (teacher of the group or substitute of one of its lessons), daily limit per teacher (default 20 recipients/day, center setting), text 1..1000 chars. Templates are fixed Uzbek texts (golden). The message goes through `outbox_messages` (the DB trigger still requires linked guardian with reminders on + active notifications consent) and the log row `teacher_guardian_messages` is immutable for everyone (no UPDATE/DELETE grant, trigger as well).
- Reminders to staff go through `staff_notifications` (in-app list + Telegram to the staff member's linked chat by the worker). Cross-center driver: a small loop in the API process (`NAZORATLY_TEACHER_REMINDER_INTERVAL_S`, default 300, off in tests); the per-center sweep is also `POST /v1/teacher-app/reminders/run` for owner/admin.
- Permissions: no new permission names; owner/admin manage (`staff:manage`), teacher uses `attendance:*`, `results:*` and the new `/v1/teacher/*` routes (any active member with a linked teacher profile).

## API (`/v1`)

Owner: `POST /teachers/{id}/invitations`, `GET /teacher-invitations`, `DELETE /teacher-invitations/{id}`, `PATCH /teachers/{id}/messaging`, `GET|PATCH /teacher-app/settings`, `GET /teacher-messages`, `POST /teacher-app/reminders/run`, `GET /lessons/unmarked`.
Auth: `POST /auth/accept-teacher-invite`, `POST /auth/telegram-miniapp`.
Teacher: `GET /teacher/me`, `/teacher/groups`, `/teacher/lessons`, `/teacher/pay`, `/teacher/notifications`, `POST|GET /teacher/guardian-messages`. Attendance, notes/grades, QR scan and the calendar use the existing endpoints (they already restrict a teacher to own groups/lessons; tests prove it).
Bot: `POST /hooks/teacher-bot` (secret header), commands `/start CODE`, `/bugun`, `/guruhlar`, `/jadval`, `/oylik`, `/xabar`, buttons for attendance and messages. Page `/ui/teacher`.

## Sheets edition

Sheets `Ustoz taklifnomalari`, `Ustoz xabarlari` (log, protected), teacher columns `Telegram chat`, `Vasiyga yozish`; settings rows; menu `Ustoz ilovasi` (invite, unmarked lessons, reminders now, owner digest now, auto-reminder trigger); the Telegram webhook understands teacher updates (link, `/bugun`, attendance buttons, `/oylik`, `/xabar`). New OAuth scope: `script.scriptapp` (time trigger for reminders). The Mini App and email/password login exist only in the API product (a Sheet has no accounts); the Sheets teacher uses the bot.
