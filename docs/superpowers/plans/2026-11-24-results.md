# G4 learning results (session S4, slug `results`, migrations 0035-0039)

Scope (design section 4, G4), both products (Postgres/FastAPI and the Google Sheets edition), shared golden tests:

1. Lesson or month **note and grade** written by the teacher; later shown in the guardian cabinet (G7 reads `GET /v1/students/{id}/results`).
2. **Monthly progress report PDF** (attendance + grade + notes + exam results). Generated as a DRAFT; sent to a guardian only after a person approves (Model B).
3. **Simple exam results**: one score per student per group event (`exam`), no question bank, no online test.
4. **Certificate PDF** at course completion with a **verification code**.

## Decisions taken here (no owner input needed, all reversible)

- Grade scale for notes: whole number 1..5 (school scale); exam score is `score` of `max_score` (any scale), reported as whole percent.
- Attendance percent in a report: `(present + late) / (present + late + absent)`, half up; `excused` lessons are outside the denominator; no lessons marked = "no data".
- Average grade: mean of the month's lesson grades and the month grade, one decimal, half up.
- Certificate eligibility: enrollment `finished`, or enrollment `active` in a group that is `finished`. Never `trial`/`frozen`. One certificate per enrollment; it can be voided with a reason, never edited or deleted.
- Verification code `NZC-XXXX-XXXX-XXXX` (12 symbols of the QR alphabet, 60 bits). Public verification returns centre, number, course, date and a MASKED holder name (privacy: no child data leaves in clear), plus valid/voided.
- Sending a report or certificate = the approving call of a signed-in person (same pattern as receipts/QR card): outbox message with a PDF attachment, consent rules enforced by the DB trigger.
- Permissions: new `results:read`, `results:write`, `results:approve` (teacher: read+write for own groups only; manager/admin/owner: all; viewer: read).

## Shared rules (pure, golden `tests/golden/results.json`)

`rules/results.py` and `sheets/src/domain/results.ts`: grade validation, attendance summary and percent, average grade, exam percent, month label (Uzbek), report caption text, certificate eligibility, number (`SR-yyyy-000001`), code generation/normalisation/validation, name mask.

## Database (migrations)

| No | Content |
|---|---|
| 0035 | `learning_marks` (note/grade per lesson or month; unique per scope; enrolment trigger) |
| 0036 | `exams`, `exam_results` (score <= max trigger; student enrolled trigger) |
| 0037 | `progress_reports`, `progress_report_files` (draft, approval fields) |
| 0038 | `certificates`, `certificate_files`, `certificate_counters`, `next_certificate_serial()`, `certificate_verify()` for the public lookup |

Each with RLS (FORCE), audit triggers, grants, down file, `db/tests/test_schema.sql` cases.

## API (`/v1`)

marks (`PUT/GET/DELETE /marks`, `GET /students/{id}/results`), exams (`/groups/{id}/exams`, `/exams/{id}`, `PUT /exams/{id}/results`), progress reports (`POST /reports/progress`, bulk `/reports/progress/generate`, list/get/pdf, `POST .../approve`), certificates (`POST /certificates`, list/get/pdf/void/send, staff verify, public `GET /v1/verify/certificate/{code}`). Teachers see only own groups.

## Sheets edition

Sheets "Baholar", "Imtihonlar", "Imtihon natijalari", "Oylik hisobotlar", "Sertifikatlar"; menu "Natijalar"; reports/certificates rendered to PDF via HTML (like receipts), Drive folder, send with a confirm dialog. No new OAuth scope expected (Drive `drive.file`, UrlFetch already present).

## Tests (test-first)

- Golden: `results.json` read by pytest and vitest.
- API: marks (validation, negative, teacher scope, enrolment), exams, report numbers vs attendance, draft -> approve -> outbox attachment, no send without approval and consent, certificate rules, verify (public masked), RLS isolation, immutability.
- Schema: `db/tests/test_schema.sql`, `db/scripts/test_migrations.sh`.
- Sheets: gas tests with the in-memory harness for each menu action.
